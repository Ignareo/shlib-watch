# 图书难借吗（shlib-watch）

周期性观测**上海图书馆**指定图书的馆藏状态，用积累的数据回答：这本书，到底有多难借？

![看板](docs/og-image.png)

## 它能回答什么

- **现在能借吗？去哪个馆借？** —— 每本书的分馆构成一目了然：可外借几册、其中几册在架、几册只能馆内借读
- **总体有多难借？** —— 易借指数（0–5 星）+ 在架率，基于每日采样积累，不靠一次碰运气
- **难借的话，要不要直接买？** —— 长期趋势图告诉你它是常年抢手还是最近刚好借完

纯静态架构、无数据库，数据全部积累在仓库里：

```
books.txt（书单）→ 采样器定时抓取馆藏 → docs/data/*.json（git 提交回仓库）→ GitHub Pages 看板
```

- 数据来源：上海图书馆馆藏书目查询系统公开页面（`vufind.library.sh.cn`），无需登录
- 采样器：Node.js ≥ 20 脚本，跑在 **GitHub Actions（定时）** 或 **你自己的电脑（本地模式，更稳）**
- 看板：纯静态网页（原生 HTML/CSS/JS + ECharts），部署在 **GitHub Pages**

## 快速开始（约 5 分钟）

1. **建仓库**：把本项目所有文件推到你自己的 GitHub 仓库（public 仓库 Actions / Pages 免费）。
2. **开 Pages**：仓库 Settings → Pages → Source 选 `Deploy from a branch`，分支 `main`、目录 `/docs`。等一两分钟，`https://<你的用户名>.github.io/shlib-watch/` 即可访问。
3. **开 Actions**：仓库 Actions 页启用 workflow。`.github/workflows/sample.yml` 已内置「每天上午 10:05（北京时间）」定时任务，也可手动点 **Run workflow** 立即采样一次。

> ⚠️ GitHub 运行机是数据中心 IP，**可能触发上海图书馆的人机验证**导致采样失败。Actions 日志里出现「触发了上海图书馆的人机验证」时，请改用[本地模式](#本地模式推荐稳定不触发风控)（家庭宽带一般不触发）。

部署完成后，编辑根目录 `books.txt` 写上你想追踪的书，等下一次采样（或手动触发）即可看到数据。

## books.txt：追踪书单

每行一本，格式：

```
书名 | 索书号 | record_id（可选）| 标签（可选，逗号分隔）
```

- 不填 `record_id` 时，采样器按「书名检索 → 索书号精确匹配」自动锁定记录；同名多版本时取副本数最多者，并在网页标注「版本待核对」
- 填了 `record_id`（检索结果页网址 `https://vufind.library.sh.cn/Record/<这串>` 里的部分）则 100% 锁定版本
- **多卷册**：一行多个索书号，用 `;` 或全角 `；` 分隔，各卷合并成一条观测记录：
  `中国建筑史 | TU-092/3965-20; TU-092/3965-17; TU-092/3965-19`
  （多索书号行不适用 `record_id`；任一索书号匹配失败会标注「版本待核对」）
- **分组**：`## 组名` 行作用于其后所有书，单独的 `##` 回到未分组；看板按组分节展示：
  ```
  ## 古建筑
  穿墙透壁 | TU-092.2/4443
  ```
- **停用**：行首加 `#` 即注释掉该书（保留历史数据，不再采样）
- **标签**（第四列）：只被采样器解析存入 index.json 存档，看板不展示
- 书 id 与历史数据按索书号集合自动关联：增删书、调整行序、合并/拆分行都不会串历史
- 看板底部的「书单助手」可图形化编辑书单（增删/分组/校验/拖拽调序），导出标准 books.txt

## 看板功能

- **易借指数**（0–5 星，星越多越好借）：由内部难借分（0–100）换算，口径为**普通外借册**（保存/参考外借/仅供阅览不计入）。在架率按平均册数折减（册数越少单册被借走冲击越大）、周末样本 ≥5 次计周末落差、最新连续 0 册在架 ≥3/≥7/≥14 天加分。悬浮/点击星星可见逐维计算明细；采样不足 3 次显示「数据积累中」。馆藏全为馆内资料的书显示「仅馆内阅览」
- **书卡**：左栏评级（易借指数 + 在架率，口径说明收进气泡）；右栏行动（行动建议 → 分馆小表 → 在架率走势 / 工作日周末对比图）。行动建议按优先级取一条：主馆在架位置 → 网借中心可约 → 全部借出（附最早预计归还日）→ 仅馆内阅览
- **观测口径**：默认只统计淮海路馆＋东馆，可在「观测口径」chips 勾选其他分馆（偏好存浏览器 localStorage）。**分馆小表只显示口径内分馆**，每馆明示「可外借 X/Y 册 · 馆内借读 Z 册」；采样时仍抓取全部分馆，改口径后分组/在架率/图表全部跟随
- **当前可借情况**：顶部把书目分为「现在可外借」「全部借出（可蹲点）」「仅馆内阅览」三组，点击定位到书卡；由不可借变可借的书带「新可借」标记
- **目录 TOC**：页面右侧浮动目录（移动端收进右下角「目录」按钮），一级为分组/书单助手/历史数据栏，点击展开二级书名直达书卡；跟随筛选联动
- **筛选**：在馆状态 pills ＋ 分组 chips，可叠加过滤
- **分享**：书卡标题旁「分享」按钮——手机调起系统分享，电脑复制带 `#card-id` 锚点的链接；页面带 Open Graph 分享卡片（部署后建议把 `docs/index.html` 里 og:image 改为绝对 URL）
- **书单助手**：载入当前书目，增删、启用/禁用、分组管理（重命名/合并/解散、拖拽调序）、索书号随改随校验；草稿自动存浏览器，「下载 books.txt」提交仓库后生效
- **历史数据栏**：勾选日期或「删除早于某日」，生成 `prune.json` 提交到 `docs/data/`，下次采样自动清理；「导出 CSV」一键导出全部历史（书 × 分馆 × 日期）

## 采样周期与请求配置（config.json）

```jsonc
{
  "schedule": {
    "frequency": "daily",        // daily / weekly / biweekly / monthly
    "weeklyDays": [3, 6],        // weekly/biweekly：周几采样（工作日+周末各一次可测周末落差）
    "anchorDate": "2026-08-17",  // biweekly：第 0 周锚点
    "monthlyDay": 1              // monthly：每月几号
  },
  "request": {
    "intervalMs": 3000,          // 请求间隔，过小可能被限流
    "timeoutMs": 25000,          // 单次超时；偶发慢响应可调到 40000–60000
    "retries": 3
  }
}
```

Actions 每天到点唤醒，是否真正采样由 `schedule` 决定，改完提交即生效。上图检索接口较慢（常需 6–13 秒），record_id 会缓存到 `.cache/records.json`，后续采样跳过慢检索。实测 7 本书：首次解析约 1 分 30 秒，缓存命中后约 15–20 秒。

## 本地模式（推荐，稳定不触发风控）

```bash
node server.js          # 本地看板：http://localhost:8765（书单助手按钮变为「重新采样」，点击即真实采样）

cd sampler && npm install
node src/index.js sample --force   # 也可单独跑采样器：立即采样一次（忽略周期）
node src/index.js check            # 查看今天是否为采样日
node src/index.js prune --before 2026-06-01   # 清理历史
```

- 采样完成后**自动 git commit + push** 数据回仓库（需本地已配推送凭据；`config.json` 关掉 `git.autoPush` 可禁用）
- 触发人机验证时自动弹出浏览器窗口（需 `npm install playwright && npx playwright install chromium`），手动过码即可，会话缓存于 `.cache/session.json`
- 定时执行：macOS/Linux 用 cron，Windows 用「任务计划程序」，每天运行 `node src/index.js sample`（不带 `--force`，尊重周期）

## 目录结构

```
├── books.txt                 # 追踪书单（唯一权威来源）
├── config.json               # 采样周期、请求限速、git 自动提交配置
├── server.js                 # 本地看板服务器（零依赖，可触发真实采样）
├── .github/workflows/        # 定时采样 workflow
├── sampler/                  # 采样器（Node ≥ 20，依赖仅 cheerio；test/ 为单测）
├── mobile/                   # 安卓 App（Capacitor），见 mobile/README.md
└── docs/                     # GitHub Pages 站点（index.html / app.js / styles.css）
    └── data/                 # 采样数据（index.json + history/*.json）
```

## 常见问题

- **Actions 采样失败，日志提示人机验证？** 数据中心 IP 被风控，改用本地模式。
- **某本书一直「未能匹配」？** 到上图检索页确认书名+索书号完全一致，或把网址里的 record_id 填进第三列锁定版本。
- **上图网页改版导致解析失效？** 采样器日志会报警，需更新 `sampler/src/parsers.js`（欢迎 PR）。
